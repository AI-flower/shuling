# XHS 内容合规规则

## 绝对禁止
- 不提及任何平台名：微信、抖音、知乎、36氪、即刻、B站、微博、YouTube、Twitter/X、Telegram、WhatsApp、Hacker News、GitHub（用"开源社区"代替）
- 不提及：区块链、虚拟货币、Web3、NFT
- 不写"用AI写小红书"类主题（会被封号）
- 不出现费用/价格信息（AI费用计算不准确）
- 不加篇数编号（文章可能被封，用户看不到连续编号）

## 格式要求
- 标题 ≤ 20 个字符
- 正文 ≤ 1000 个字符
- 标签 5-8 个，不超过 10 个
- 封面必须有互动 CTA（"告诉我你想用AI做什么，我来出教程"）
- 最后一页必须有收藏/关注引导

## 写作风格
- 口语化、有真人感
- 适量 emoji，不过度
- 允许偶尔的错误标点、同音字替代（的地得混用、在再互换）
- 痛点 → 解决方案 → 效果展示 结构
- 不能读起来像 AI 生成

## 对话气泡方向
- 用户（🧑）在右边
- OpenClaw 龙虾（🦞）在左边

## 高互动标题模式
1. 数字清单体："10个AI技能"、"5个宝藏工具"
2. 反差悬念体："被吹上天，普通人到底怎么用？"
3. 结果导向体："3分钟搞定500行数据"
4. 身份共鸣体："打工人"、"一人公司"、"替你上班"
5. 保姆级体："手把手"、"0基础"、"纯新手"

## 选题与标题升级规则
- 不要长期重复 `X到底值不值`、`X别乱上手`、`X适合谁` 这三种模板
- 标题优先写：
  - 人群 + 结果：`打工人先装这6个Skill`
  - 人群 + 错误：`新手别先装这3个Skill`
  - 顺序 + 后果：`OpenClaw别按这个顺序装`
  - 单 Skill + 一句话收益：`这个skill最适合长期项目`
- 标题不能直接使用仓库 slug、英文截断词、README 原句
- 标题必须让用户一眼知道：
  - 这是给谁看的
  - 它替我省哪一步
  - 或者我会踩什么坑
- 正文第一屏先讲：
  - 错法
  - 痛点
  - 后果
  三选一，不要先做百科定义
- 如果是清单帖，每个条目必须写：
  - skill 名字
  - 替你省哪一步
  - 适合谁/不适合谁
- 如果是单 skill 帖，至少要写：
  - 它最值的一点
  - 它不适合谁
  - 怎么判断要不要先装
- 不允许把平台新闻、创始人故事、仓库八卦当正文主体，正文主体必须是 skill 本身
- 没有真实证据支撑时，不要强写“爆款结论”

## 内容质量标准（决定是否有人看、收藏、分享）

**教程类必须满足：**
- 第4页是完整操作教程，读者跟着步骤走能真正跑起来
- 每步有：标题 + 具体操作（含完整命令/设置路径）+ 成功标志
- 前置条件/准备工作单独列出（环境、账号、文件）
- 常见错误和解决办法要有
- 命令要可复制可运行，不能模糊（"安装依赖" → `pip install langflow`）

**内容深度要求：**
- 每页至少有3-5个信息点，不能是标题+一句话
- 功能介绍要结合实际场景（"如果你要做XXX，可以用它的YYY功能"）
- 对比效果要量化（"以前需要30分钟" → "现在3分钟"）

**避免的错误：**
- 整页只有大标题和装饰图案，没有文字内容
- 步骤只有名字没有具体操作
- 每步只有一句话
- 功能列表没有场景说明
- 正文出现 README 英文原句、HTML 标签、Markdown 表格残片
- 标题和封面看起来像仓库介绍页，而不是给人收藏的笔记
